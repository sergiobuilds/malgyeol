- [ ] 2. 같은 도구: 프로필/새 요구 저장, JSON 계약, 네 사업 안내, 기관 질문과 응답. 기존 requestDetails 재사용. 시민 정보 전달은 필드별 동의로 제한. Python/실제 Node HTTP 검증.
- [ ] 3. HTTP 오류·접수 중복 방지: 확정 실패 재시도, 결과 불명 대조, 개인정보 없는 진단. HTTP 경계에서 실패를 주입해 검사.
- [ ] 4. 기관 경로와 회신: 시험 매핑 사전 검사, 프로필 공유·재고/배달 답변·조건 변경·시민 선택 반영. 임의 기관 발신 차단. 동일인 다중 접수에도 실제 발신한 번호로 회신.
- [ ] 5. 전체 Node/Python/설치 SDK 검사와 코드 리뷰. 비공개 A/B 매핑에서 기존 정미경 citizenRef를 연결하고 23시 시연 설정. 서비스 전환 영향과 승인 확인.
- [ ] 6. 실제 등록 왕복, 조건 변경, 미등록 왕복. 준비된 수신자·기존 20통/60분 한도. 제공 완료를 조율 완료와 구별. commit/push 및 인계 기록.

## 설계·위험

운영 프로세스와 기존 점유가 있는 checkout은 변경하지 않고 별도 worktree에서 개발한다. 공개 번호 수신 허용은 임의 발신 허용이 아니다. 번호는 모델 밖의 비공개 journal에 보관하고 회신은 해당 요청에 결박한다. 데모 프로필 조회는 명시 등록 번호에만 적용한다. 통화 컨텍스트에는 기존 이력을 제공하되 새 필요를 별도 요청으로 만든다. 과거 조건을 신규 요구에 복사하지 않는다.

- 운영 070/API/voice는 변경하지 않았다. 서비스 전환, 세 가지 실제 사람 음성 왕복, 최종 commit/push는 남아 있다.

### 배포 준비 검증 (13시대)

- 위 모델 입력 실패를 구조화된 도구 계약으로 수정했다. create_request/request_data, revise_request/changes, record_consent/consent_data, record_answer/answer_data는 SDK에 객체 스키마를 전달하며 기존 업무 검증 함수를 공통 사용한다. 모델이 추가한 외곽 status는 승인 근거로 쓰지 않고 버린다.
- 기존 대시보드에서 읽은 정미경 프로필로 첫 인사→새 식사·전달 접수→기관 조회→문의 준비→동의→finish까지 실제 Live 모델로 실행했다. 일반 발신자 접수와 기관 답변, 시민 회신·수령 선택·주소 추가·추가동의·동일 기관 재문의 준비도 격리 모델 시험으로 확인했다. 텍스트 입력과 격리 HTTP 저장소를 썼으므로 사람의 실제 전화 성공은 아니다.
- 실제 HTTP/SQLite 검사는 기관 문의→시민 선택→기관 재문의→최종 시민 안내까지 수행하며, 30분/45분 조건 차이와 중복 발신 방지를 확인한다.
- 동의 부분 인용 차단, 접수 후 프로필 저장 및 변경 정보 재동의, 각 필요의 문의 준비, 기관 답변 없는 종료 차단, 접수 없는 시민의 명시 종료 경로를 보완했다.
- 기관·시민회신 저장 결과 불명은 내부 멱등키로 대조한다. 영구 충돌은 해당 통화만 수동 대조 상태로 격리하여 다른 요청을 막지 않는다.
- 배포 전 읽기 전용 검사: 등록 번호 2개가 기존 정미경 citizenRef에 연결됨, 공개 접수 활성, 승인된 기관 시험 연결 40개, 시나리오 시각 23:00. 기존 journal에 종료 마커 없는 통화는 0개였다. 실시간 전화망의 활성 통화 확인을 대신하는 수치는 아니다.
- 팀원 추가 커밋 e4e8af8/cac18af(로그인 없는 웹 흐름/인계)을 발견했다. 이 변경을 보존해 통합한 후 API·음성 서비스 전환 승인을 요청한다. 현재 운영 서비스는 아직 변경하지 않았다.
