# 말결 — 지도 (MASTER-MAP)

> 사용자 승인 방향을 보존하는 현재 브랜치의 작업 지도다. 라우터 판정은 `observe-only`이며 canonical `master`에는 지도가 없다. 이 파일의 frontmatter는 프로젝트 전체 방향 권한을 부여하지 않는다. managed 전환·완료는 주장하지 않는다.

## 1 Project Charter

- 목표: 앱 사용과 외출이 어려운 시민도 전화로 자신의 사정을 말하고, 기존 복지자원에서 필요한 지원을 부탁하고 고를 수 있게 한다. 첫 이용자는 재가 어르신이다. [D-20260917-02]
- 제품 정의: 이용자 동의 아래 협약기관 사이에서 품목·일정·전달 방법을 조율하는 전화 대리인. 여러 통화와 기관 응답에 걸쳐 하나의 생활지원 요청을 이어간다. [D-20260917-02]
- 핵심 문제: 이용자가 사업을 찾아 자기 사정을 반복 설명하고, 거절·품절·일정 변경 때 다시 조율해야 하는 부담. 단순 AI 상담이나 이행 검증을 대표 가치로 삼지 않는다. [D-20260917-02]
- 최종 산출물: 생활 제약에 맞는 선택·대안 협의·기관 전달·변경 후 재협의를 보여주는 전화 프로토타입, 수행기관 업무함과 사람 이관, 서울시 정책·데이터·실증환경·지원 제안 1장. 정산·증빙은 참여기관을 위한 내부 운영 기반이다. [D-20260917-02]
- 승리·성공 논리: 상담형 구현과 비교해 이용자의 재설명·재통화와 직원 조정 부담을 줄이며 지원 연결을 이어가는 것을 보여준다. 기술 우위·비용절감률·경쟁자에게 없는 기능·수상 가능성은 미입증이며, 전화가 된다는 사실과 구분한다. [D-20260917-02]
- 가드레일: AI는 신규 자격·급여·개인별지원계획을 결정하지 않는다. 승인 범위 밖 요청과 위험 신호는 사람에게 이관한다. 개인정보를 최소화하고 미제공 서비스를 제공한 것처럼 기록하지 않는다. [D-20260917-01, D-20260917-02]
- 명시적 비목표: 이용자 결제, 범용 쇼핑, 농식품바우처 잔액 소비, 암호자산·블록체인, 서울시 기존 시스템 전면 교체, 24시간 공공기관 처리를 주장하지 않는다. [D-20260917-01]

## 3 Confirmed Scope

기존 결정의 경계를 아래에 보존한다. 적용 범위는 3.1의 최신 결정으로 보완하며, 계획 기반 서비스와 별도 자격 사업을 구분한다.

- 법적 뿌리는 돌봄통합지원법과 서울시 지역사회 돌봄 통합지원 체계다. [D-20260917-01]
- 말결은 개인별지원계획을 새로 판단하지 않고 승인된 서비스를 전화로 실행한다. [D-20260917-01]
- 긴급 식사는 돌봄SOS, 식품·생필품은 찾아가는 푸드마켓 또는 가정 배달이 가능한 협약 수행기관에 연결한다. [D-20260917-01]
- 기존 주문 성공 업체와 배달 플랫폼은 정책 기반이 아니라 자치구가 승인할 때만 쓰는 교체 가능한 공급자 어댑터다. [D-20260917-01]
- 첫 공공 실증에는 이용자 결제 기능을 포함하지 않는다. [D-20260917-01]
- 정상 요청은 수행기관으로 직접 전달하고 예외만 공무원에게 이관해 행정업무를 줄인다. [D-20260917-01]
- 프로젝트 저장소는 비공개·권리유보 원칙을 유지하며 외부 팀원에게 전체 저장소 권한을 전제로 하지 않는다. [D-20260917-01]

### 3.1 대안 협의와 제한적 위임 [D-20260917-02]

- 기존 공급망 전체를 유지한다. 첫 실증은 자치구 1곳과 소수 협약기관으로 제한하되 식사 정산 하나로 제품 범위를 축소하지 않는다.
- 새 복지급여를 만들거나 예산을 합치는 것이 아니라 기존 사업의 이용·전달 절차를 연결하는 실증을 제안한다. 사업별 자격·승인·예산은 유지하며 모든 사업에 동일한 개인별지원계획을 요구하지 않는다.
- 전화 연결 → 동의·필요한 본인 확인 → 생활 제약·선호 파악 → 제공 조건 조회 → 대안 제시·선택 → 기관 전달 → 응답에 따른 후속 협의가 목표 흐름이다. 자동 실행은 협약으로 허용된 범위에 한정한다.
- 대표 요청은 “쌀은 있지만 조리가 어렵고, 비누도 필요하며, 방문할 수 없다”다. 식사·생필품을 가능한 경로로 나누고, 한 기관의 품절·일정 변경이 와도 처음부터 재설명하지 않게 한다.
- 365일 24시간은 AI 응대·접수의 운영 목표이지 현재 가용성 보장이나 기관의 24시간 제공 약속이 아니다. 발신은 동의한 시간과 목적 안에서 하며 아직 구현 완료로 표시하지 않는다.
- 기억은 이용자가 확인한 선호·제약·진행 중 요청을 최소한으로 보존하는 설계다. 일시적 제약과 지속 선호, 추측과 확인된 사실을 구분하고 수정·삭제 경로를 둔다.
- 음성은 Gemini를 유지한다. 국산 LLM은 대안 조합 후보로 비교하되 SOLAR 채택·국산 음성·전체 국내 처리를 확정하지 않는다. 모델 API 추가 호출과 운영 전환은 별도 승인 대상이다.
- 기술 개발의 초점은 생활 맥락 표현, 조건 기반 대안 생성, 통화 종료 후 이어 처리, 변경 부분만 재협의다. Tessera의 선언형 규칙과 Ouroboros의 오케스트레이션은 재사용 가능성을 확인할 대상이며 돌봄용 DSL·비용절감이 이미 구현됐다고 쓰지 않는다.
- 정산은 기부물품의 제공 기록, 비용 발생 서비스의 사업별 청구, 승인 민간계약의 증빙을 구분한다. OCR는 추출을 돕고 지급·분쟁의 최종 판단은 담당자가 맡는다.
- 정책 패널의 질문: “시민이 동의하면 AI가 협약 복지기관 사이에서 품목·일정·전달 방법을 대신 조율하도록 허용할 수 있는가?” 위임 범위, 기관 정보공유·갱신 책임, 실패 시 담당자 인수를 구체화한다. 법 개정이 필요한지는 미확인이고 표준 운영협약으로 가능한지 먼저 확인한다.

### 3.2 다음 집중 과제 — 대표 시연 하나 [D-20260917-02]

우선순위는 기능 수를 늘리는 것이 아니라 위 대표 요청에 기관 거절·품절 또는 일정 변경 1회를 넣어, 이용자가 다시 설명하지 않고 대안을 선택하는 장면을 만드는 것이다. 아래는 다음 실행 계획이며 완료 증거가 아니다.

1. 현장 담당자·수행기관에게 동일 상황의 현재 처리 절차와 위임 가능 범위를 확인한다. 실제 장애물이 없다면 정책 논리를 수정한다. 외부 접촉은 별도 승인 후 수행한다.
2. 초기 요청 → 이용자 선택 → 기관 응답 지연/거절 → 재협의 → 변경 요청 전달을 동일 요청으로 시연한다. 실제 전화와 합성 기관 응답은 명확히 구분한다.
3. 동일 조건의 상담형 구현과 비교할 항목을 재설명·재통화·직원 조정시간·연결 결과·응답 지연·총비용으로 고정한다. 모델별 결과와 절감률은 아직 없다.
4. 시연에서 드러난 권한·정보·책임의 빈틈을 정책 제안 1장에 연결한다. 기능 설명만을 정책 요구로 포장하지 않는다.

대표 시연은 성능 평가 자료와 분리한다. 비교 과제는 현장 담당자가 별도로 제공하고 정답·제공 가능 조건은 모델이 아닌 기관 자료에 근거한다. 두 구현에 동일한 정보와 도구 접근을 제공하고, 가능하면 시스템 이름을 가린 외부 평가자가 판단한다. 개발팀이 만든 성공 시나리오만으로 일반적 우위를 주장하지 않는다.
