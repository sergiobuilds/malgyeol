# 말결 아키텍처

## 설계 원칙

1. AI는 의미를 구조화하지만 정책이나 금전 결정을 내리지 않는다.
2. 승인한 조건과 실제 실행 조건이 다르면 실행하지 않는다.
3. 사건은 덮어쓰지 않고 추가해 감사 가능한 이력을 만든다.
4. 외부 공급자와 호스팅 환경은 교체 가능한 어댑터로 둔다.
5. 자동화 실패는 숨기지 않고 사람의 업무함으로 넘긴다.

## 모듈

| 경로 | 책임 |
|---|---|
| `src/food-support/` | 요청 해석, 품목 정책, 예산, 카탈로그 연결 |
| `src/case-ledger/` | 사건 상태, 정규 해시, 순서·재생 방지, 역할별 투영 |
| `src/http/` | 공개·이용자·운영자 API와 접근 경계 |
| `src/voice/` | 서명된 전화 입력과 음성 해석 어댑터 |
| `src/merchant/` | 공급자 주문 계약과 샌드박스 구현 |
| `src/e2e/` | 접수부터 승인·결제·주문까지의 오케스트레이션 |
| `src/providers/` | AI·음성·공급자·호스팅의 교체 가능한 계약 |
| `src/legacy/` | 기관용 XLSX 내보내기 호환 계층 |
| `public/` | 제품 소개, 이용자·운영자 화면, 기술 경계 |

## 권한 분리

- **AI 해석기:** 의도, 정규화된 질의, 확인 필요 여부만 반환합니다.
- **정책 엔진:** 버전이 고정된 규칙으로 품목·예산·중복 여부를 판정합니다.
- **이용자 확인:** 조건 해시와 승인 revision을 확정합니다.
- **결제 실행기:** 확정된 금액과 조건에 대해서만 승인 참조를 만듭니다.
- **공급자 어댑터:** 승인된 품목과 수량만 주문하고 공급자 참조를 반환합니다.
- **사건 원장:** 각 단계의 주체, 시간, 입력 해시, 결과를 기록합니다.

## 배포와 주장 경계

기본 개발·시연 경로는 메모리 저장소와 합성 데이터를 사용합니다. 영속 저장소는 도메인 인터페이스 뒤에 격리됩니다. 현행 중립 결제 원장은 과거 기술 실험과 섞이지 않는 `canonicalCasesV2` 컬렉션을 사용합니다. 과거 사건은 현행 사건으로 자동 승격하지 않습니다. 현재 확인 범위는 자동 테스트와 로컬 샌드박스이며 실제 공공 지원금, 정부 시스템, 실결제, 실제 수혜자 데이터 또는 공식 기관 채택을 주장하지 않습니다.

프로덕션 전환 전에는 개인정보 영향 검토, 보존·삭제 절차, 키 관리, 백업·복구, 공급자 계약과 운영 책임자를 별도로 확정해야 합니다.
