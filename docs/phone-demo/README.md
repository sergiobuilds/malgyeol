# 전화 체험 시연 인계 — audience 모드

## 현재 범위

실제 전화한 사람의 위치·필요·제약을 듣고 Seed를 만든 뒤, **1번 승인 / 2번 수정**을 받습니다. 승인하면 통화를 종료하고 고정된 모의 기관 목록과 비교한 결과를 같은 발신번호로 회신합니다. 결과 뒤 “더 말씀하실 내용이 있으세요? 통화를 마치려면 1번을 눌러 주세요”라고 안내하며, 실제 1번 입력 후 종료합니다.

사전 페르소나·정미경 사례·60초 전용 인터뷰는 사용자 지시로 제외했습니다. 이름·주소·동의를 미리 채우지 않습니다. 음성 “네”로 승인하지 않습니다. 기존 상품 주문·실제 기관 발신·실제 음식 배송은 없습니다.

## 운영 설정

기존 API/음성 서비스에 코드를 같이 반영하고 아래를 설정합니다. 비밀값은 기존 비공개 설정을 사용합니다.

```dotenv
# API
DEMO_WORKFLOW_ENABLED=true
DEMO_WORKFLOW_LEDGER_PATH=.private/phone-demo-workflow.sqlite
DEMO_WORKFLOW_SCENARIO=success
# Voice
COORDINATION_DEMO_MODE=1
COORDINATION_DEMO_EXPERIENCE=audience
COORDINATION_DEMO_ALLOW_AUDIENCE=1
```

`ALLOW_AUDIENCE=1`은 미등록 수신자의 체험을 명시적으로 허용합니다. 회신 대상은 SDK가 받은 실제 발신번호에 고정하며 AI가 번호를 지정하지 못합니다. 기본 `standard` 모드는 기존 등록 번호 제한을 유지합니다. 동시에 여러 통화를 처리하는 기능은 포함하지 않습니다.

비공개 `coordination-routing.json` 파일은 여전히 필요합니다. audience 시연은 빈 시민/기관 매핑도 허용하며 실제 기관 역할 B는 필요하지 않습니다. 기존 실제 기관 모드는 A/B 검사를 유지합니다.

```bash
# 운영 서버의 기존 비공개 환경에서 수행
python3 scripts/run-care-runtime.py coordination-check
# API/voice 실행은 기존 서비스 단위로 전환. 중복 음성 프로세스 금지.
```

## 모의 기관 목록

고객 요구를 복사해 성공 응답을 만들지 않습니다. 서버 시작 때 고정하는 모의 목록은 서초구/AI허브 지역, 한 끼 식사 1인분, 무료, 배달 또는 방문 수령, 별도 식이 제한 없는 조건입니다. 향후 12시간 동안 30분 간격의 제공 시각을 미리 생성합니다. 이미 지난 시각을 미래처럼 안내하지 않습니다.

지역·품목·수량·비용·수령·식이·기한이 맞지 않으면 실패 또는 미확인 결과를 정확히 설명합니다. `unavailable`과 `no-answer` 시나리오도 선택할 수 있습니다. 기관명 A/B/C는 허구이며 모든 결과에 시연임을 표시합니다.

## 검증과 실제 전화의 경계

로컬 HTTP/SQLite/실제 Python bridge와 fake SDK 전송으로 성공·불가, 음성으로는 승인되지 않음, 숫자키 수정·승인, 실제 발신번호에 고정된 콜백, 키 입력 전 종료 차단, 중복 콜백 방지, 재시작 보존을 검증합니다. Node 22 전체 230/230 PASS, Python+실제 SDK 클래스 42/42 PASS입니다. 성공/불가 × standard/audience의 로컬 HTTP↔Python 통합 4개 시나리오를 검증합니다. 실제 전화는 하지 않았습니다.

콜백은 통화 종료 후 즉시 SDK 발신을 요청합니다. 기록은 종료→SDK 발신 시작과 SDK 반환을 분리하며 **실제 전화망에서 3초 이내 벨 울림을 보장하지 않습니다.** 사용자 실제 전화 검증은 아직 남아 있습니다.
